## Реализация по разделу 10 syllabus

| Обязательное требование | Реализация и доказательство |
| --- | --- |
| Три страницы, сохранение HTML | Добавлены только классы и 4 stylesheet-ссылки; DOM-сравнение с `lab-1/markup` сохранило элементы, текст, атрибуты и их порядок |
| Mobile-first: 375 / 768 / 1440 | Каталог: 1 / 2 / 3 колонки; на 768 навигация в строку; на 1440 фильтры слева |
| Шапка Flexbox с переносом | `.site-header`, `.site-nav ul`, `flex-wrap`, `gap` |
| Каталог Grid | `repeat(auto-fit, minmax(min(100%, var(--card-min)), 1fr))`, минимум 260 px с защитой узкого контейнера |
| Равная высота карточек и кнопки внизу | Внешний Grid растягивает карточки ряда; внутренние строки `auto auto auto 1fr auto`; тест с названием из 15 слов |

| Reduced motion | Анимаций, переходов и smooth scroll нет ни при одной настройке; проверены `reduce` и `no-preference`. Отдельный media query не нужен |
| 14+ токенов | 46 уникальных переменных: палитра, отступы, радиусы, шрифты, размеры, тени |
| Четыре CSS-файла | `tokens.css`, `base.css`, `layout.css`, `components.css`, в таком порядке |
| Соглашение классов и селекторы | Имена блоков и элементов вроде `book-card__button`, модификаторы `main--loan`; максимум два уровня селектора |
| Ограничения CSS | Нет `!important`, ID-селекторов, фиксированной ширины контейнеров и межсоседних margin. Цвета, отступы и визуальные размеры компонентов взяты из токенов |
| Media queries | Ровно 2: тёмная тема и `min-width: 900px`; числовой breakpoint записан в условии, где CSS custom properties не работают |
| 320 px без горизонтальной прокрутки | Все три страницы, обе темы; дополнительно диапазон 320–1600 с шагом 16 px |
| Состояния форм | Нативные `:invalid:user-invalid`, `:focus-visible`, `:disabled`; ошибка появляется после взаимодействия, фокус сохраняет контрастный outline |

`0`, `1fr`, `100%` и номера Grid-линий задают структуру раскладки, а не произвольные визуальные размеры. Оформление задаётся токенами. Секции не превращены во вложенные карточки; фон и рамка предназначены для повторяющихся книг.

Все баллы из файлов [`lighthouse/summary.json`](lighthouse/summary.json). Полные отчёты: `lighthouse/{index,book,loan}-{light,dark}.{json,html}`. Остаются диагностические замечания о кешировании, сжатии, цепочках запросов и блокирующем CSS; высокий итоговый балл не означает отсутствие всех замечаний.

**Ограничение баллов:** часть изображений недоступна во время аудита. Оценка 100 не доказывает полную загрузку изображений или готовность реального сайта; после восстановления сети Performance следует измерить повторно.

[`browser-results.json`](browser-results.json): 30 проверок viewport/theme, 6 проходов фокуса и форм, 2 стресс-теста карточек/футера (38 записей). Проверки структуры, колонок, высот, фокуса, пустых форм и reduced motion прошли. В файле намеренно сохранены **30 failures**, все типа `broken image`: это повторение сетевого дефекта в каждой комбинации страницы, темы и ширины. Скрипт завершился с кодом 1; этот запуск не объявляется полностью успешным.

[`interaction-results.json`](interaction-results.json): 6 проходов по 81 ширине, всего **486 проверок без overflow**. Реальные переходы по трём пунктам навигации прошли. Проверены неправильный и правильный email, состояние disabled кнопки и фокус invalid-поля: outline 3 px в обеих темах. Ошибок CSS-проверок нет. Отдельное поле `inheritedNamePattern` содержит дефект ЛР1 и не входит в массив CSS failures.

## Обнаруженные проблемы и ограничения

1. **Внешние обложки.** Solaris, 1984 и Sapiens не загрузились в каталоге; обложка Solaris также не загрузилась на book/loan. Open Library отвечает 302 и отправляет на `archive.org`, после чего соединение из этой среды завершается тайм-аутом. Пример реальных заголовков: [cover-http-headers.txt](cover-http-headers.txt). Команда `curl.exe -sS -IL --max-time 30 -o docs/lab2/cover-http-headers.txt https://covers.openlibrary.org/b/isbn/9780156027601-M.jpg` завершилась кодом 28. Источники изображений унаследованы из ЛР1. Заглушек, перехвата запросов и подмены ответов не было. Нужно проверить их из сети с доступом к archive.org либо отдельно согласовать локальные копии и изменение `src`, выходящее за ограничение ЛР2 «только классы».
2. **Невалидный pattern ФИО из ЛР1.** В `loan.html` завершающий дефис внутри символьного класса не экранирован для современного режима регулярных выражений `v`. Реальный тест: `123` не вызывает `patternMismatch`, конструктор RegExp выдаёт SyntaxError. Исправление вне CSS: заменить конец класса ` .-]` на ` .\-]`, затем отдельно проверить буквы, пробелы, дефис и цифры. В этой ветке атрибут сохранён, чтобы не нарушить ограничения изменения HTML и не смешать исправление ЛР1 со стилизацией.
3. **Макеты и broken.css отсутствуют.** Сравнение с преподавательским макетом и исправление его пяти конкретных дефектов не выполнены. Связанная практика/СРС описана в [css-debug.md](../css-debug.md); теоретическая памятка не выдаётся за выполненную практику.
4. **Исходные функциональные ограничения.** Фильтры и POST-формы не имеют обработки данных на этапе HTML/CSS; каталог по-прежнему содержит одну демонстрационную detail-страницу. JavaScript не добавлялся. Тексты ЛР1, включая подпись футера, сохранены.
5. **Защита и PR.** Нужна демонстрация студентом, объяснение Layout-инспектора и токенов. ЛР1 ещё не объединена с main. Push, создание PR, merge и rebase не выполнялись.

В процессе реализации сокращены слишком глубокие селекторы кнопок до `.book-card__button`, исправлен приоритет оформления фокуса invalid-поля, исключено преждевременное подсвечивание пустых обязательных полей. В автоматизации исправлено ожидание внешних картинок в подготовительной вкладке Lighthouse. Финальный просмотр снимков обнаружил ещё одну ошибку: тема отдельной подготовительной вкладки не задавала тему вкладки Lighthouse, и первые отчёты с меткой light фактически были тёмными. Скрипт исправлен: Puppeteer задаёт media feature непосредственно странице, передаваемой четвёртым аргументом Lighthouse, и проверяет её после аудита. Все шесть отчётов получены повторно; прежние неверно размеченные результаты заменены новыми реальными запусками, история коммитов сохранена.

## Воспроизведение

Из корня репозитория (PowerShell), одноразовые инструменты в игнорируемом каталоге:

```powershell
npm.cmd install --prefix .audit-tools --no-save --package-lock=false playwright@1.58.2 lighthouse@12.8.2
node tools/lab2-audit.mjs
node tools/lab2-interactions.mjs
node tools/lab2-lighthouse.mjs
```

Нужны установленный Edge по пути `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`, Python в PATH, свободные порты 8122–8124 и 9242, доступ в сеть. Browser-аудит и Lighthouse поддерживают `BROWSER_PATH`; дополнительный interaction-аудит использует Edge явно. Скрипты не подключены к HTML, в приложении нет npm-зависимостей. Запускать последовательно; повторный запуск обновляет доказательства. `node tools/lab2-lighthouse.mjs dark` повторяет только тёмную тему и сохраняет светлые результаты.

Первый browser-аудит завершится ненулевым кодом, если обложки останутся недоступны. Не удалять такие failures ради «зелёного» результата. Чтобы увидеть страницы без аудита, достаточно открыть `../../index.html` напрямую.

Контроль изменений: `git diff lab-1/markup...lab-2/styles`, `git log --oneline lab-1/markup..lab-2/styles`, `git diff --check`. Ветки предыдущих работ не изменялись.
