## Браузерные сценарии

Скрипт `tools/lab5-browser.mjs` запускался в настоящем Edge:

- 4/4 реальных сценария: поиск и страница 2; wishlist после перезагрузки; Slow 4G и отмена устаревшего запроса `ERR_ABORTED`; Offline с Retry; детали Solaris и реальный HTTP 404.
- 6/6 контролируемых сценариев с моками: debounce/фильтры, безопасный текст, empty, HTTP 429, HTTP 503, некорректный JSON и восстановление Retry.
- 18/18 комбинаций: каталог, детали и форма; 375, 768 и 1440 px; light и dark. Во всех `scrollWidth` равен ширине viewport.
- В обычных сценариях: 0 `pageerror`, 0 ошибок консоли. В журнале отдельно оставлены ожидаемые ошибки Offline и 404.

Исходные измерения: `browser-results.json` и `network-real.json`. В `screenshots/` сохранены 13 изображений, включая реальные состояния каталога, деталей, Slow 4G, Offline, шесть обязательных вариантов каталога и React DevTools.

## Исправления по результатам проверки

- Wishlist-empty отделён от взаимоисключающих состояний каталога, чтобы на экране не появлялись два состояния одновременно.
- Добавлена локальная иконка, устранившая лишний 404 в обычной консоли.
- Внешние обложки скрываются при ошибке загрузки и не блокируют данные книги.
- Тест хранения приведён к экспортируемому ключу `API_STORAGE_KEY`.
- Lighthouse-аудит очищает сохранённый запрос перед каждым независимым снимком; после исправления завершены все шесть запусков.

## Воспроизведение

```powershell
cd booknest-web
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

Браузерные скрипты используют пакеты из игнорируемой `.audit-tools` и локальный Edge:

```powershell
node tools/lab5-browser.mjs
node tools/lab5-accessibility.mjs
node tools/lab5-checks.mjs
node tools/lab5-devtools.mjs
```

## Известные ограничения

- Реальные результаты зависят от сети и текущих данных Open Library. Моки используются только для воспроизводимого контроля ошибок и не выдаются за ответы сервиса.
- Wishlist сохраняется для текущего origin; при запрете `localStorage` приложение продолжает работать только в памяти.
- Форма выдачи не имеет backend и подтверждает только прохождение нативной валидации.
- На защите студенту остаётся показать интерактивное дерево React DevTools, объяснить владельцев состояния и запустить build. Сохранённый снимок не заменяет устную защиту.
- Push, создание PR, merge и действия ЛР6 не выполнялись.
