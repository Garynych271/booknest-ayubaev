## Самостоятельная часть

Подтверждена после буквального выравнивания API: [`Badge.tsx`](../../booknest-web/src/shared/components/Badge.tsx) имеет union `variant="ok" | "busy" | "warn"`. Компонент применяется в карточке, деталях, wishlist и форме выдачи; все три варианта используются. CSS опирается на токены.

## Владельцы состояния

- `App` владеет фильтрами, страницей и wishlist, потому что ими пользуются несколько соседних компонентов и они должны согласованно сохраняться.
- `CatalogPage`/позднее hook владеет lifecycle конкретного API-запроса, который не нужен всему приложению.
- `BookCover` хранит только локальное состояние загрузки изображения.
- Производные `saved`, количество страниц и отфильтрованные данные вычисляются, а не дублируются в state.

## Что показать вручную

1. Открыть React DevTools → Components и выбрать `BookCard` с ключом OL…W.
2. Изменить boolean prop `saved`, показать изменение текста/`aria-pressed`, затем вернуть значение.
3. Включить highlight updates, изменить поиск и показать, какие компоненты перерисовались.
4. Объяснить, почему filters находятся выше `FiltersPanel` и `BookList`.

## Краткие ответы для защиты

- State поднимается до ближайшего общего владельца всех потребителей, но не выше без причины.
- Индекс массива нельзя использовать как key: после сортировки React может связать локальное состояние карточки с другой книгой.
- Props описывают внешний контракт компонента; локальный state хранит только принадлежащее самому компоненту изменяемое состояние.
- Иммутабельное обновление создаёт новую ссылку, по которой React обнаруживает изменение.
- `Badge` презентационный: его вид определяется props, собственного состояния и предметной логики у него нет.

Challenge task `Modal` не выполнялся: он необязателен.
